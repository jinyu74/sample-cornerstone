## 새 사용자 규칙 반영 (리뷰 승인과 병합 허가 분리)

1. PR 오픈 전 감독 Codex 사전 검수는 그대로 두고(6절), PR 오픈 후 단계로 Codex 리뷰어를 추가했다(1절, 2절 11단계, 7.1).
2. 리뷰어는 `review-agent` 스킬을 실제로 읽고 전체 merge diff를 읽기 전용으로 독립 리뷰한다. head가 바뀌면 다시 리뷰하고, 파일 수정·커밋·푸시·리뷰 댓글 게시·병합을 하지 않으며, 지적은 감독 Codex와 Claude에 전달한다.
3. 리뷰 결과 게시(7.2, 사용자 확정 임시 방식)
   - 감독 Codex가 같은 계정(`jinyu74`)으로 판정·지적·검증·리뷰 head SHA를 PR 댓글에 게시하고, 이 댓글이 정식 Approve review가 아님을 댓글과 문서에 명시한다.
   - 같은 계정의 자기 PR Approve 금지 제약 때문에 정식 Approve review는 별도 인증 주체 결정 전까지 보류한다. 이번 작업을 막는 질문은 없다.
4. 병합 허가(7.3·7.4)
   - 사용자가 직접 병합하거나, 해당 PR·head에 대해 명시적으로 병합을 요청한 경우에만 감독 Codex가 병합한다.
   - 리뷰 결과 댓글, 일반 동의, 사용자 검토 승인, Claude 완료 보고는 병합 허가가 아니며, 명시 병합 요청 전에는 무조건 병합하지 않는다.
   - 병합 요청 뒤 head가 바뀌면 재리뷰와 재요청이 필요하다.
   - auto-merge를 금지한다.
5. 기록(7.5): 리뷰 기록(정식 Approve 아님 문구·판정·지적·검증·PR·리뷰 head)과 병합 요청 기록(출처·PR·head)을 따로 남긴다.
6. 이전 정책 문구(사용자 직접 확인 승인 → Codex 병합, "승인 기록", "승인한 head")를 `docs/development-workflow.md`, `AGENTS.md`, `CLAUDE.md`, PR 템플릿에서 모두 새 정책으로 바꿨다.

## 미검증

- GitHub에서의 실제 표시: 기본 브랜치에 반영한 뒤 새 이슈·PR 작성 화면에서 템플릿 선택·적용 상태를 확인해야 한다. 현재는 파일 경로와 frontmatter·내용을 검증했다.
- 감독 Codex는 `AGENTS.md`의 링크를 따라 공통 문서를 직접 읽고 검수했다. 다른 세션에서도 시작 지침에 따라 해당 문서를 읽어야 한다.
- 링크 검사 범위: 앵커 검사는 GitHub 슬러그 규칙을 근사한 스크립트로 했다. GitHub 화면에서 앵커 이동을 직접 확인하지는 않았다.
