# DICOM 측정·라벨링 작업 지시서

당신은 이 프로젝트의 구현 담당 Claude Code 에이전트다. 한국어로 소통한다.
작업 시작 전에 `AGENTS.md`, `CLAUDE.md`, `docs/development-workflow.md`를 읽고 Codex가 지정한 이슈·작업 브랜치·담당 범위에서만 구현한다. 이 문서는 앱 기능 범위를 설명하며 새로운 작업 지시가 기존 구현 전체의 재작성을 뜻하지는 않는다. PR 생성과 별도 패널 Codex 리뷰어의 `$review-agent` 검토 조율은 감독 Codex가 담당한다. 리뷰 승인은 병합 허가가 아니며 사용자가 직접 병합하거나 명시적으로 병합을 요청한 경우에만 감독 Codex가 병합한다.
사용자는 Next.js와 TypeScript로 실제 동작하는 DICOM 영상 작업 앱을 만들고자 한다.
현재까지의 아이디어 수집은 완료했으며, 아래 범위의 구현을 진행한다.

## 작업 원칙

- 현재 작업 디렉터리를 확인하고 기존 파일, AGENTS.md, CLAUDE.md를 먼저 읽는다.
- 사용자 지침으로 /Users/jinyu/.codex/RTK.md도 읽는다.
- 런타임과 개발 도구 버전은 mise로 관리하고 프로젝트 mise.toml에 명시한다. 패키지 설치, 의존성 관리, 스크립트 실행은 pnpm을 사용하며 잠금 파일은 pnpm-lock.yaml을 사용한다.
- AGENTS.md의 테스트 우선 개발, FSD 기반 관심사 분리, 모델·타입 분리, 커스텀 hook, shadcn/ui 확장, Storybook 컴포넌트 라이브러리, 품질 검사와 Codex 검수 규칙을 따른다.
- 기능 구현 전 시나리오와 인수 조건을 정의하고 테스트의 의도된 실패를 확인한 뒤 구현한다. 작업 단위별 결과와 검사 근거를 왼쪽 Codex에 보고하여 검수받는다.
- 기존 작업을 보존한다. 프로젝트가 비어 있으면 이 디렉터리에 프로젝트를 구성한다.
- 공식 문서와 설치할 패키지 버전에서 실제 지원하는 기능을 먼저 확인한다. 구형 Cornerstone 예제와 최신 API를 혼합하지 않는다.
- 짧은 구현 순서와 선택한 버전을 설명한 뒤, 일반적인 구현 선택은 자율적으로 진행한다.
- 아래 '사용자 결정'에 해당하면 질문한다. 답변이 필요 없는 독립 작업은 계속한다.
- 실제 DICOM 렌더링과 결과 복원이 동작해야 한다. 모형 UI만 만들거나 미지원 기능을 동작하는 것처럼 표시하지 않는다.
- 요청되지 않은 배포, 외부 서비스 생성, 실제 환자 데이터 전송은 진행하지 않는다.

## 확정된 제품 방향

브라우저에서 DICOM 영상을 열어 측정값과 메모를 남기고, 병변·장기에 라벨을 지정하는 작업 도구다.
단일 영상과 다중 슬라이스에 별도 앱이나 별도 버전을 만들지 않는다.

- 기본 표시 엔진은 Cornerstone3D StackViewport로 한다.
- 단일 프레임은 영상 1개, 다중 슬라이스는 영상 목록으로 처리한다.
- 단일 DICOM 파일의 멀티프레임도 고려한다. 파일 개수와 프레임 개수를 혼동하지 않는다.
- 단일 영상에는 슬라이스 탐색 컨트롤을 숨기거나 비활성화한다.
- 멀티프레임이 공간 슬라이스인지 시간 프레임인지 메타데이터에 따라 구분한다.
- MPR/3D가 필요해질 경우 동일 작업 화면에 VolumeViewport 모드를 추가할 수 있게 경계를 설계한다.
- 모든 다중 영상이 3D 볼륨으로 재구성 가능하다고 가정하지 않는다.

## 기술 검토

- Next.js App Router + TypeScript를 사용한다.
- @cornerstonejs/core, @cornerstonejs/tools, @cornerstonejs/dicom-image-loader의 호환 버전을 확인한다.
- 뷰어는 클라이언트에서 초기화하고 SSR 중 브라우저 API가 실행되지 않게 한다.
- Worker와 WASM codec의 개발·프로덕션 로딩을 확인한다. 현재 Next.js bundler와의 호환성을 검증한다.
- 뷰어 엔진의 가변 상태와 React의 화면·폼 상태를 적절히 분리한다.
- 파일·메타데이터·주석 저장소에 인터페이스를 두어 이후 서버 저장소를 연결할 수 있게 한다.
- 초기 저장소는 IndexedDB로 원본 파일과 작업 결과를 브라우저에 보관한다. 용량 제한, 저장 실패, 사이트 데이터 삭제 시 유실 가능성을 UI와 문서에서 명확히 알린다.
- 초기의 파일 가져오기는 로컬 처리다. 서버 전송 기능이 없는 상태에서 '서버 업로드 완료'라고 표시하지 않는다.

## 1차 구현 범위

### 검사 목록과 파일 가져오기

- 검사(Study) → 시리즈(Series) → 영상·프레임 구조로 관리한다.
- 검사 목록에 검사 날짜, 식별자, modality, 시리즈 수, 작업 상태를 표시한다.
- 검색과 작업 상태 필터를 제공한다. 작업 상태는 미작업 / 작업 중 / 완료로 한다.
- 여러 파일 선택과 드래그앤드롭을 제공한다. 폴더 선택은 브라우저 지원 여부에 맞춰 대체 경로를 제공한다.
- DICOM 파싱 결과로 검사·시리즈를 묶고 진행 상태, 성공·실패, 실패 이유를 표시한다.
- 파일 확장자만으로 DICOM 여부를 판단하지 않는다.
- SOP Instance UID를 기준으로 중복을 처리하되, 충돌 시 조용히 덮어쓰지 않는다.
- 서로 다른 검사나 시리즈를 하나의 스택으로 섞지 않는다.
- CT/MR 공간 정렬은 유효한 위치·방향 메타데이터를 우선한다. 파일명 순서만으로 슬라이스를 정렬하지 않는다.
- 멀티프레임의 프레임별 메타데이터와 미지원 transfer syntax를 적절히 처리한다.

### 영상 작업 화면

- 상단: 도구 선택, 실행 취소·다시 실행, 저장, 저장 상태.
- 왼쪽: 시리즈 목록과 썸네일.
- 중앙: 실제 DICOM 영상과 측정·주석 오버레이.
- 오른쪽: 작업 결과 목록, 선택한 결과의 라벨·측정값·메모 편집.
- 하단: 현재 영상 또는 프레임 위치와 로딩 상태.
- 한국어 UI, 어두운 영상 영역, 읽기 쉬운 패널과 선택 상태를 제공한다.
- 확대·이동, Window/Level, 반전, 회전, 화면 맞춤·초기화를 제공한다.
- 다중 영상에서는 휠과 슬라이더로 이동한다. 그리기 도구와 입력 동작이 충돌하지 않게 한다.
- 시리즈 이동·화면 이탈 때 미저장 변경을 유실하지 않게 한다.

### 측정·메모·라벨링

- 길이와 각도 측정.
- 타원 ROI와 다각형 또는 닫힌 자유곡선 윤곽 중 공식 API로 안정적으로 구현 가능한 도구.
- 화살표 또는 위치 주석과 메모.
- 주석 선택, 좌표 편집, 삭제, 표시·숨김, 실행 취소·다시 실행.
- 장기·병변 라벨을 선택하고 사용자 정의 라벨을 추가·수정할 수 있다.
- 라벨에는 이름, 색상, 분류(장기/병변)를 둔다.
- 개별 대상(entity) 식별자와 라벨 종류를 구분한다. 같은 병변을 여러 슬라이스에 표시할 때 하나의 대상으로 묶을 수 있게 한다.
- 결과 목록 선택 시 해당 시리즈·영상·프레임으로 이동하고 주석을 강조한다.
- 물리적 보정 정보가 유효한 경우에만 mm/mm² 단위를 사용한다. 보정이 없으면 px/px² 등 실제 계산 단위를 표시한다.
- 측정값은 좌표와 보정 정보에 따른 계산 결과로 관리한다.
- 윤곽 주석과 픽셀·복셀 segmentation mask를 구분한다. 윤곽만 구현한 상태를 3D 장기 분할 완료라고 설명하지 않는다.

### 저장과 복원

- 원본 DICOM을 보존하고 작업 결과를 별도로 저장한다.
- 결과 스키마에 버전을 둔다.
- StudyInstanceUID, SeriesInstanceUID, SOPInstanceUID와 필요시 frame number, 좌표계, FrameOfReferenceUID, 도구 종류, 좌표·윤곽, 대상 ID, 라벨 ID, 메모, 시간 정보를 보관한다.
- 화면 canvas 좌표만 저장하지 않는다. 원본 영상에 다시 대응할 수 있는 영상 또는 world 좌표와 참조를 저장한다.
- 스택 순번만으로 프레임을 식별하지 않는다. 정렬과 재진입 후에도 올바른 영상으로 복원되어야 한다.
- 자동 저장 상태와 수동 저장을 제공하고, 저장 실패를 성공으로 표시하지 않는다.
- 작업 결과 JSON 내보내기·가져오기를 제공한다. 다른 영상의 결과를 잘못 연결하지 않게 검증한다.
- JSON 결과에 원본 픽셀 데이터가 포함되는지와 재연결에 필요한 조건을 명시한다.

## 후속 확장과 사용자 결정

현재 구현을 막지 않는 항목은 docs/decisions.md에 질문·권장안·영향을 기록한다.
구현을 막는 결정은 질문 내용과 권장안을 한국어로 간결하게 알리고 답변을 기다린다.

1. 서버에 원본 영상과 결과를 보관할지, 로컬 전용으로 유지할지. 초기 기본값은 로컬 전용이다. 서버 업로드는 미구현임을 명시한다.
2. 브러시·지우개·임계값 기반 픽셀/복셀 영역 분할이 첫 출시의 필수인지. 초기 기본값은 측정·2D 윤곽 라벨링이다.
3. MPR, 3D 표시, 슬라이스 간 보간, 3D 부피 계산의 필요 여부. 초기 범위에는 포함하지 않는다.
4. 사용자 계정, 공동 작업, 검수·승인 역할의 필요 여부. 초기 기본값은 단일 사용자다.
5. 병원/PACS 연동과 DICOM SR·SEG 결과 교환의 필요 여부. 초기에는 버전 있는 자체 JSON을 사용한다.

새 유료 서비스, 서버 인프라, 임상 용도에 대한 결정을 임의로 확정하지 않는다.
이미 정한 Next.js/TypeScript, 통합 뷰어, 측정·메모·라벨링 방향을 다시 승인받지 않는다.

## 검증과 완료 조건

- 단일 영상, 다중 파일 CT/MR 스택, 멀티프레임을 각각 검증한다. 샘플이 없거나 형식이 미지원이면 그 범위와 미검증 사실을 기록한다.
- 공개·비식별 샘플 또는 합성 fixture를 사용한다. 사용자의 다른 폴더에서 환자 파일을 임의로 가져오지 않는다.
- 측정·메모·라벨 생성 → 수정 → 저장 → 새로고침 → 동일 영상·위치 복원 흐름을 브라우저에서 확인한다.
- 시리즈 간 주석 혼입, 삭제 후 부활, 이중 초기화, 이벤트·GPU 자원 누수를 확인한다.
- 좌표 복원, 단위 보정, UID/frame 연결, 잘못된 결과 import에 의미 있는 테스트를 작성한다.
- 관련 테스트, 타입 검사, lint, format 검사, 프로덕션 빌드, Storybook 빌드를 실행하고 이 세션의 Codex 검수를 받는다.
- README에 실행 방법, 지원 확인 범위, 로컬 저장 특성, 구현된 기능과 미구현 기능을 구분해 기록한다.
- 마지막에 구현 결과, 검증 결과, 남은 제약, 사용자 결정 항목을 한국어로 보고한다.
